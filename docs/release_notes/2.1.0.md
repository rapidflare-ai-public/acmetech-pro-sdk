# AcmeTech Pro SDK 2.1.0 release notes

(Fictional demo content; see NOTICE.md.)

## Required steps

**Pro-100 rev B: call `atp_hal_pwr_trim_apply()` after every deep sleep wake-up.**
Erratum PRO100-E7: on rev B silicon the core regulator trim returns to its
reset value when the chip leaves deep sleep. Active current is then about 18%
above the datasheet value (around 4.1 mA instead of 3.5 mA at 192 MHz) until
the next reset. `atp_hal_pwr_trim_apply()` restores the factory trim. It is
safe to call on every part; it does nothing on Pro-29 and Pro-100 rev C.
`examples/deepsleep_wake` shows where it goes. `bsp_resume_from_sleep()` does
not call it for you.

## New

- SPI: `ATP_SPI_CLK_32MHZ` on Pro-100. The AcmeTech Displays Pro-84 panel
  still tops out at 24 MHz.
- `atpflash --verify` reads the image back after writing it.
- `atp_hal_pwr_chip_rev()` returns the silicon revision.

## Fixed

- I2C: `atp_hal_i2c_recover()` now stops as soon as SDA is released.

## Known issues

- Pro-29: with `ATP_HAL_VALIDATE=0`, asking for `ATP_SPI_CLK_32MHZ` gives
  24 MHz without an error.
